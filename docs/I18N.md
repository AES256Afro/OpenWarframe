# Other languages

## Status

- **Reward helper: done (0.12.0).** Pick your game client's language in the Reward helper view.
  OpenWarframe downloads that language's item names once and reads reward screens in it. All 15
  languages the game ships are supported: English, Deutsch, Español, Français, Italiano, 日本語,
  한국어, Polski, Português, Русский, ไทย, Türkçe, Українська, 简体中文, 繁體中文.
- **Item names in the app and exports: done (0.13.0).** Settings > **Item names** shows the names of
  items, parts and relics in any of the 15 languages, in every view, in Live, in item details and
  in the exports (Excel, CSV, JSON, SQLite, dashboard, guide, LLM brief). The CLI takes
  `openwarframe export --names de` (default: the app's setting).
- **The app's own text: English only.**

## Where the names come from

DE's Public Export is published per language (`index_<lang>.txt.lzma`) with the same
`uniqueName` keys as English. `codex/languages.py` downloads the manifests with names
(resources, warframes, weapons, companions, relics and arcanes, mods, gear, cosmetics, quests,
drones) and keeps `uniqueName -> name`.

Recipes have no name in the export. The game builds "Rhino Prime Blueprint" from a pattern,
`/Lotus/Language/Items/BlueprintAndItem`, which warframe-public-export-plus ships per language
in `dict.<lang>.json`: `|ITEM| BLAUPAUSE` (German), `ЧЕРТЁЖ: |ITEM|` (Russian), `|ITEM|の設計図`
(Japanese) and so on. Each recipe gets that pattern filled with its result's name.

The table is saved in `<data folder>/names/<lang>.json` (about 1.4 MB), apart from the game
database, and rebuilt when DE's export for that language changes (checked when game data is
updated in the app).

## Matching

`live/match.py` normalizes with Unicode NFKC, upper-cases, and keeps letters of every script.
Accents on Latin, Greek and Cyrillic letters are dropped (OCR often misses them: SCHÉMA,
ЧЕРТЁЖ); marks that are part of a letter in other scripts (Japanese dakuten) are kept. Each
reward is matched on its name in the game's language and shown with its English name.

## OCR

The OCR engine gets the game language's tag (`de-DE`, `ja-JP`, `zh-Hans`, ...). Japanese,
Korean and Chinese use a taller name box (58 px instead of 48 px at 1080p, from WFInfo).
On Windows the OCR language must be installed (Settings > Time and language > Language, add the
language with its optical character recognition feature); without it Windows falls back to
the profile's languages and reads worse. macOS's text recognition supports these languages
without extra installs.

## Tested

On macOS (Apple Vision), drawn sample screens with four random rewards, five screens per
language: 20 of 20 rewards matched in every one of the 15 languages. Real game screenshots in
languages other than English are still to be checked.

## How item names are shown

Everything inside OpenWarframe still works with English names: some rules read them ("Kuva"
weapons come from a Lich, a Prime is the copy to keep). So translation runs last, on what is
shown (`codex/translate.py`): by uniqueName where a row carries one, otherwise by exact English
name for known fields (`name`, `part`, `for`, `relic`, `what`, ...). Free text is never changed.
App rows keep the English name as `name_en`, so search finds both.
